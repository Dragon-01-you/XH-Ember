> 使用方法：把本文件**整份**作为提示词交给检索 AI。不要删节，删任何一节都会让结果失去穷尽性。

## 0. 你的角色与交付物

你是资深技术调研员，专长云产品与合规。你的交付物是一份**可以被工程团队直接拿去设计产品**的调研报告。

三条铁律：

1. **只给事实与证据，不给建议、不给方案、不评价好坏。**
2. **每一条结论后面必须带：来源链接 + 核查日期 + 可信度等级。**
3. **查不到就写「未找到」。绝不许编造产品名、接口名、政策条文。** 编造一条，整份报告作废。

**先做一件事**：用不超过 300 字，给出你的检索计划（准备从哪些站点、用什么关键词、按什么顺序查）。等我确认后再展开全文。

## 1. 背景（决定你要往哪个方向挖）

我们在做一个**本地运行的 AI 应用**：帮不懂技术的人（典型：中国专科在读学生）把他**已经做好的项目**部署到公网，让他在手机上打开一个真实可访问的地址。

用户画像决定了检索重点：

- **没有企业主体，没有国际信用卡**，只有支付宝 / 微信、身份证、学生身份；
- **不懂英文文档**，看不懂控制台；
- 项目形态：AI 工具生成的网页应用、带后端和数据库的小系统、或纯静态页面；
- 他要的是「**今天就能看到**」或者「**长期能对外用**」，这两件事的路径完全不同。

现有产品的痛点我们已经知道一部分（见第 2 节），但**产品空间还没穷举**——这正是需要你做的。

## 3. 检索范围：六个平面（MECE）

六个平面互斥且合起来覆盖「一个项目从本机到公网可访问」的全部要素。**每个平面都要穷举，不许挑着答。**

### 平面一 · 计算载体（项目跑在什么上面）

1. 能让**中国个人（无企业资质）**把项目跑起来并公开访问的载体类型有哪些？逐类穷举：虚拟主机 / 轻量应用服务器 / ECS / VPS / Serverless 函数 / PaaS / 静态托管 / 容器托管 / 边缘运行时 / 建站工具。
2. 每一类里，**列出具体产品名**（国内 + 海外），不许只给类别。
3. 每个产品：支持哪些语言/运行时？支持从**已有 Git 仓库**部署，还是只能从零生成？
4. 免费额度是多少？免费额度的**真实限制**是什么（休眠、过期、限流、广告、强制升级）？
5. 是否要求绑定支付方式？接受哪些支付方式？
6. 有没有"一键创建、平台代管服务器"的产品？它们和"给你一台裸服务器"的区别在哪？

### 平面二 · 网络与寻址（别人怎么找到它）

1. **穷举各家的默认域名 / 预览域名**：域名形态、有效期、能否长期公开、有无中间页/强制下载/token/限流/每日额度。
2. 自定义域名：能不能绑？要什么材料？要不要备案？HTTPS 证书从哪来？是否收费？
3. **纯 IP 访问**：哪些产品支持用 IP 直接访问？有无端口限制（80/443 是否被封）？有无 HTTP 拦截？合规边界是什么？
4. **平台子域名的备案归属**：平台主域名已备案，是否覆盖用户子域名？法律依据与实际执行情况如何？
5. 大陆 CDN / WAF 与备案的联动规则是什么？
6. 域名实名认证要求、`.cn` 与 `.com` 的差异。

### 平面三 · 数据与存储（数据放哪）

1. 各平台提供的托管数据库：类型、免费层、**过期策略**、备份、迁移出成本。
2. 对象存储：默认域名访问 HTML 是否强制下载？自定义域名是否必须备案？
3. 数据物理位置（境内 / 香港 / 海外）对合规的具体影响。
4. 静态站点 + 数据库的常见组合方式，哪些平台支持"一次创建就自带数据库"？

### 平面四 · 身份、支付与合规（谁能开、能不能合法开）

1. 实名认证：哪些平台强制？需要什么材料？**海外平台是否要求中国身份证 / 护照**？
2. 支付：逐个产品列出接受的支付方式（支付宝 / 微信 / 银联 / 国际信用卡 / PayPal），**特别标注「中国个人能否付款」**。
3. ICP 备案：完整流程、材料清单、各环节耗时、**个人主体与企业主体的差异**、经营性 vs 非经营性。
4. 公安联网备案：什么情况下必须办？香港/海外服务器是否也要办？
5. 微信小程序 / 公众号「业务域名」是否强制要求 ICP 备案？
6. 使用大陆 CDN / 全站加速时，备案要求如何变化？
7. 数据出境、跨境传输的合规要求。

### 平面五 · 交付生命周期（怎么上去、怎么更新、怎么退回）

1. 代码怎么上去：Git 集成 / CLI 上传 / FTP / SSH，逐个产品说明。
2. 构建在哪里发生：平台构建 vs 自建构建？构建时长限制？
3. 更新与**回滚**：是否有一键回滚？保留多少个历史版本？
4. 日志与监控：免费额度多少？保留多久？
5. 域名与证书续期：会不会因为忘记续期导致下线？
6. 故障排查入口：官方状态页、工单、社区支持分别在哪？
7. **产品变更/下线公告的发布渠道在哪**（这是最容易踩的坑，必须列清每家去哪个页面看）。

### 平面六 · 市场格局与产品化程度（谁已经在做、做到什么程度）

1. 已有**帮小白上线**的产品有哪些？逐个列：产品名、厂商、目标用户、价格、覆盖哪些路径。
2. 哪些产品支持「**从已有仓库 / 已有项目**一键部署」（注意：不是从提示词生成，而是部署已有代码）？
3. **AI 编程工具自带的部署能力**全清单：Qoder Sites、CodeBuddy、Trae、Cursor、Claude Code、Windsurf、通义灵码、CodeGeeX 等，各自能部署到哪、额度多少、有没有域名。
4. 这些产品的**共同空白**是什么？（哪些环节没人做，或做得明显不够）
5. **已停服 / 已下线 / 已改名的产品清单**（必须单列，避免我们推荐死产品）。

## 5. 必须单独回答的八个「关键未知」

这些是我们自己搜不到、必须靠你深挖的：

1. **Qoder Sites 的真实限制**：每日访问额度具体数值、是否支持绑定自定义域名、是否支持任意现有项目（有无技术栈限制）、商用条款、内容审核政策。
2. **SAE Web 应用下线后，阿里官方给出的替代方案是什么**？是 FC + 自定义域名吗？成本与迁移路径？
3. **各家控制台里「学生认证 / 优惠资格 / 券可用性」具体长在哪个页面**？有没有隐藏 API 能读到（我们已核实大部分读不到，需要确认是否存在未公开接口）。
4. **香港轻量服务器在中国大陆三大运营商的实测表现**：延迟、带宽、是否被限速、晚高峰情况。要真实用户实测，不要官方宣传。
5. **ICP 备案的真实天数**，分省份统计（找真实用户分享，不要官网的"5–20 工作日"）。
6. **纯公网 IP 访问的合规边界**：是否被要求备案？运营商是否封 80/443 端口？有没有人因此被约谈或关停？
7. **平台子域名长期公开的真实案例**：有没有人用 `*.tcloudbaseapp.com` / `*.qoder.zone` 这类地址长期对外提供服务且没被封？活多久？
8. **各家"部署池 / 一键发布"类产品的隐藏限制**：并发、带宽、冷启动、单文件大小、构建时长、每日构建次数。

## 6. 证据标准（不合规的结论直接删除）

给每条结论标可信度：

- **A 级**：官方文档原文 / 官方公告 / 法条原文（必须给链接 + 原文引用）
- **B 级**：官方定价页 / 官方客服答复 / 官方 GitHub 仓库
- **C 级**：开发者社区问答、有截图的用户实测帖
- **D 级**：二手博客、营销号、教程视频

**规则**：
- A、B 级可以直接采信；C 级必须标注「用户实测，未官方确认」；**D 级只能作为线索，不能作为结论依据**。
- 涉及到**产品是否存在、是否下线、是否支持某功能**的结论，**必须 A 级**。
- 每一条都要写**核查日期**（这类产品平均半年就变一次）。

## 7. 反例检索（必做，且单独成章）

官方文档只会说好话，你要专门去找另一面：

- 搜「`<产品名>` 踩坑 / 翻车 / 被封 / 限流 / 账单爆炸 / 下线 / 迁移」
- 找因**未备案被关停**、因**免费额度用完断服**、因**平台改政策**而被迫迁移的真实案例
- 找「以为免费结果收费」的账单案例
- 找「默认域名突然不能用了」的案例

每条案例要写：产品、发生时间、后果、来源链接。

## 8. 输出格式

- Markdown，章节编号与本文档**一一对应**（第 3 节六个平面、第 4 节总表、第 5 节八个未知、第 7 节反例）。
- 开头给**不超过 500 字的结论摘要**。
- 以表格为主，散文为辅。
- 全文长度不限，宁长勿短；但每一句都要有出处。
- 最后单列一节「**本次未找到 / 存疑的项目**」，把你查了但没查实的列出来，不要为了凑数而写。

## 9. 禁止事项

1. 禁止编造产品名、接口名、政策条文、价格数字。
2. 禁止把二手博客当作唯一来源。
3. 禁止推荐已下线 / 已停止维护的产品。
4. 禁止给「建议」「方案」「你们应该做 X」。
5. 禁止省略链接。
6. 禁止用"通常""一般来说"搪塞——要么给具体产品具体数字，要么写「未找到」。
7. 禁止只查官网：必须同时查**官方公告页、定价页、开发者社区、真实踩坑帖**三类来源。
