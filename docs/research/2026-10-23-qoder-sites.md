# Qoder Sites：厂商域名下的「部署池」

2026-10-23｜来源：Qoder 官方文档 + 官方新闻稿 + 用户实测帖

## 结论

用户的记忆是对的。阿里 Qoder 有一套「部署池 + 厂商域名」的东西，叫 **Qoder Sites**（2026-09-20 上线）。
它给用户一个挂在**厂商自己域名**下的子域名，既不需要用户买域名，也不需要备案。

另外澄清一处：**Qoder 是阿里云的，不是腾讯的**（前身是通义灵码团队的产品线）。

## 已核实事实

- **域名形态**：用户实测帖中出现的真实站点为 `class-homework-hcva9wq3cr5.qoder.zone`，
  即 `*.<随机串>.qoder.zone`。域名归厂商，用户只拿到一个部署位。
- **上线时间**：2026-09-20；Qoder v0.3.3 与 Qoder CLI v1.1.54 起支持。
- **能力**：从零建站，**或从已有项目构建**后发布（内置技能 `sites:sites-building`）；
  可带数据库、server functions、对象存储（Agent App）。
- **权限**：私有 / 指定成员 / 组织 / 公开；转公开需二次确认。
- **可程序化调用**：`qoder sites` 子命令，JSON 输入输出；
  `list_sites`、`get_site`、`check_subdomain`、`get_analytics` 等只读操作可直接脚本调用；
  构建发布链路由会话内技能携带 session 调用（`prepare_site` / `publish_site`）。
- **写操作需显式确认**：发布、删除、改分享策略、删 Secrets 前，会复述影响并等待确认。
- **有每日访问额度**：用户实测帖（班级作业网站，57 人提交）当天触发
  「该站点今日访问额度已用完」，次日 00:00 UTC 重置。官方**未公开**具体额度。
  该帖回复里"限制极严、几十次请求"属个人推测，**不可作为事实引用**。

## 这修正了上一份调研的一个结论

上一份《部署产品现状》写下："在国内，免备案与可长期公开访问只能二选一。"
**这句话说得太死了。** 更准确的说法是：

> 在国内，**不备案**意味着你**不拥有域名**——站点挂在平台自己的备案域名下（如 `*.qoder.zone`）。
> 你不需要备案，代价是**受平台的额度、审核与政策约束**。

平台域名之所以能免备案，是因为主域名本身已备案，子域名继承它；用户既不需要、也无法单独为其备案。

## 对产品的含义

1. 「厂商域名 + 部署池」这条路真实存在，而且**可被程序调用**（CLI + JSON），不必依赖浏览器自动化。
2. 但它**有硬额度**：适合"先看到效果"，不适合"正式承载"。
3. 于是自然分成两层：
   - **体验层**：发到 Qoder Sites 类平台 → 分钟级、零配置、免备案、有额度；
   - **正式层**：香港轻量服务器（免备案、可长期）或国内轻量 + 备案。
4. 上一份调研的"硬约束"要撤回，改成"分层约束"。
