# 流程梳理（需求对齐结论 v1）

> 状态：需求对齐阶段的收口。尚未写规格书。所有用词以 `GLOSSARY.md` v4 为准。

## 一句话

一个**本地运行、有状态、不上传数据**的「部署大师」：
扫描项目 → 逐层提问 → 给出 2–3 个方案并明确推荐 → 用户确认 → 备份后执行 →
在五个关键节点停手 → 交付一个**手机能真实跑通**的地址。

## 七段流程

### 第 0 段 · 启动
- 本地应用，打开只有一个聊天窗口
- 不注册、不登录
- 唯一联网是调用模型（模型由用户自己配）

### 第 1 段 · 扫描 → 项目画像
- **读**：代码、配置文件、依赖清单、环境变量名
- **不读**：数据库里的数据行（ADR-0003）
- **产出**：项目画像（技术栈 / 有无后端 / 有无数据库 / 是否纯静态 / 依赖哪些外部服务）
- 结果写进**状态目录**（本机，不上传）
- 三种失败必须分开报：读不到 / 没权限 / 确实没有

### 第 2 段 · 逐层提问
- 一层一层问，每问都带推荐答案；答不上来就按推荐走
- 问题树的起点：给谁看 → 国内还是海外 → 今天就要看到还是能等 → 预算 → 有没有域名 / 服务器

### 第 3 段 · 判断（部署大师）
- 读取「项目画像 + 问答记录」
- 先查**预置路径**：命中就直接走
- 不命中 → **元方法**现场推导
- 都推不出来 → **明确拒绝**，说清为什么

### 第 4 段 · 出方案
- **2–3 个完整组合**，每个包含：厂商 / 配置 / 套餐 / 估算月费 / 环境要求 / 能否长期公开
- **一个明确推荐 + 3–5 行理由**，理由要用小白能听懂的话
- 技术内容拆开讲，讲完再问「可以执行吗」
- **用户确认之后才执行**

### 第 5 段 · 执行
- **先备份**：数据库内容 + 服务器关键配置；保留 3 份、覆盖 3 个月
- 五处**硬拦截**：实名认证、绑卡、选套餐、付款、备案提交
- 域名：做到「选好 + 停在付款页」→ 用户自己付款与实名 → 我们做解析、HTTPS、绑定
- 按预置路径或元方法推导出的步骤执行

### 第 6 段 · 验收（「跑通」四条）
1. 手机打得开
2. 首页渲染出来
3. 一次真实的后端请求成功
4. 数据库写入后能读回，并在页面上显示

### 第 7 段 · 失败处理
- 有备份，可退回上一个可用状态
- 代码问题：小问题可小修；**主要是让用户拿他自己的本地 AI 去修**；大问题说明清楚、不负责修复
- 拒绝修复的情况也要说清「这是你的代码问题，不是部署问题」

## 状态是怎么存的

- 一个本机目录（状态目录），按项目分开
- 里面放：项目画像、问答记录、已选方案、备份索引
- **不上传任何东西**
- 部署大师每次启动先读它，所以「记得」上次聊到哪

## 四件必须再确认的事（本文件不定，等用户拍板）

1. **危险项默认删除** —— 与"不可逆动作必须停手"冲突，建议改为隔离
2. **已有服务器** —— 从"第一版不做"改为"帮部署、不帮运维"，范围要写清
3. **小问题反馈给模型提供方** —— 本地应用没有通道，需要落地方式
4. **状态目录是否加密** —— 密钥放哪？建议不加密，但状态目录里不存任何凭证
